# ForexRL Bridge — Deployment Guide

The Python bridge connects your trained RecurrentPPO model to MetaTrader 5 via FastAPI.

---

## Directory Structure

```
forex_rl_bot/
├── models/
│   └── rppo/
│       └── v1/
│           ├── final_model.zip       ← trained model
│           └── model_info.json       ← generated by save_model_info.py
│
├── deploy/
│   ├── main.py                       ← FastAPI server
│   ├── predictor.py                  ← inference engine
│   ├── state.py                      ← session & performance tracking
│   ├── dashboard.html                ← live monitoring UI
│   ├── save_model_info.py            ← one-time setup utility
│   └── requirements.txt
│
└── ForexRL_EA.mq5                    ← MetaTrader 5 Expert Advisor
```

---

## Setup

### 1. Prepare the model directory

The bridge expects models in a versioned layout:

```
models/{algorithm}/{version}/final_model.zip
```

**If your model is in the legacy path (`models/forex_ppo/final_model.zip`):**

```bash
mkdir -p models/rppo/v1
cp models/forex_ppo/final_model.zip models/rppo/v1/
```

The server auto-detects the legacy path and serves it as `rppo/v1`.

**For new models (trained with run.py train):**
Training now saves directly to `models/rppo/v1/` — no action needed.

---

### 2. Generate model_info.json (one-time)

`model_info.json` stores the exact observation feature list in the order the model was trained with. This guarantees live inference matches training.

```bash
# From the project root:
python deploy/save_model_info.py
```

This creates `models/rppo/v1/model_info.json`.
Re-run any time the feature pipeline changes.

---

### 3. Install dependencies

```bash
pip install -r deploy/requirements.txt
```

---

### 4. Start the bridge

```bash
# From the project root:
uvicorn deploy.main:app --host 0.0.0.0 --port 8000

# With auto-reload during development:
uvicorn deploy.main:app --host 0.0.0.0 --port 8000 --reload
```

Open the dashboard: **http://localhost:8000**

---

### 5. Configure the MT5 EA

1. Copy `ForexRL_EA.mq5` to your MT5 `Experts/` folder
2. Compile in MetaEditor
3. Attach to an EURUSD M15 chart with these settings:

| Parameter | Value |
|-----------|-------|
| BridgeURL | `http://YOUR_SERVER_IP:8000` |
| SessionID | `mt5_session_01` (unique per terminal) |
| ModelAlgo | `rppo` |
| ModelVersion | `v1` |
| CandleHistory | `300` |
| StartingBalance | Your actual account balance |

4. In MT5 → Tools → Options → Expert Advisors:
   - ✅ Allow WebRequest
   - Add URL: `http://YOUR_SERVER_IP:8000`

## Multi-Model Support

Multiple algorithms and versions can run simultaneously.

### Adding a second model

```bash
mkdir -p models/ppo/v1
cp <your_ppo_model.zip> models/ppo/v1/final_model.zip
python deploy/save_model_info.py
```

Restart the server. Both models load automatically.

### EA model selection

Set the EA inputs:
- `ModelAlgo = "ppo"` / `ModelVersion = "v1"`

Or use `rppo` / `v1` for the original model.

### API endpoints

| Endpoint | Description |
|----------|-------------|
| `POST /rppo/v1/predict` | Versioned inference |
| `POST /ppo/v1/predict` | Another model |
| `POST /predict` | Default model (backward compat) |
| `GET /models` | List all loaded models |
| `GET /health` | Server health |
| `GET /metrics` | Live performance snapshot |
| `GET /history` | Closed trade log |
| `WS /ws` | WebSocket dashboard |

## Automated 3-Phase Training

Training is automated. Running `python run.py train` executes all phases in sequence:

| Phase | Data | Steps | Purpose |
|-------|------|-------|---------|
| phase1_foundation | 2010–2016 | 2M | Broad market structure |
| phase2_general | 2010–2024 | 500k | Full historical fine-tune |
| phase3_recent | 2025 | 200k | Recent price action adaptation |

Each phase saves `final_model.zip` and `model_info.json` to `models/rppo/v1/`.

To skip a phase, set `"skip": True` in `config.TRAINING_PHASES`.

To run a single phase:
```python
from training.train import train_phase
import config
train_phase(config.TRAINING_PHASES[0])   # phase 1 only
```

## Production Deployment (Linux VPS)

### systemd service

Create `/etc/systemd/system/forexrl.service`:

```ini
[Unit]
Description=ForexRL Bridge
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/forex_rl_bot
Environment=BOT_ROOT=/home/ubuntu/forex_rl_bot
ExecStart=/home/ubuntu/.venv/bin/uvicorn deploy.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable forexrl
sudo systemctl start forexrl
sudo journalctl -u forexrl -f   # follow logs
```

### Firewall

```bash
sudo ufw allow 8000/tcp
```


### Test the endpoint manually

```bash
# Health check
curl http://localhost:8000/health

# List models
curl http://localhost:8000/models

# Metrics
curl http://localhost:8000/metrics
```

### Common issues

| Symptom | Cause | Fix |
|---------|-------|-----|
| EA trades nothing | Action bug (old code) | Upgrade EA to v2.00 |
| 503 on /predict | No model loaded | Check model path, see /health |
| Shape mismatch error | model_info.json missing | Run save_model_info.py |
| P&L not tracked | HistorySelect missing (old EA) | Upgrade EA to v2.00 |
| Bridge not reachable | Firewall / URL | Add MT5 WebRequest URL |

## Key Design Decisions

**Why versioned endpoints?**
Different model versions may have different observation spaces or position sets. Versioning prevents accidentally routing an RPPO v2 request to a PPO v1 model.

**Why model_info.json?**
gym-trading-env adds `feature_close_pct` internally and uses DataFrame column order (not sorted). Without saving the exact feature list at training time, live inference would silently use the wrong observation — model sees garbage, trades randomly.

**Why HistorySelect() before HistoryDealsTotal()?**
MT5 requires you to first select a history window before accessing it. The old EA omitted this call, meaning `HistoryDealsTotal()` always returned 0, and the bridge never received trade close notifications.
